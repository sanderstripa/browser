# Startup, New Tab and Home

Independent per-profile settings use `startupMode/startupUrl`, `newTabMode/newTabUrl` and `homeMode/homeUrl` in `Profiles/<id>/soulu-settings.json`. Startup supports `continue`, `soulu`, `custom`, and `blank`. New Tab and Home support `soulu`, `custom`, and `blank`. Persisted legacy `startPageMode/startPageUrl` migrate to Startup only; old controls remain compatible with Startup. Invalid or empty stored custom URLs fall back to the local Soulu page; UI mutations reject non-web addresses, credentials, whitespace, and executable schemes.

`+`, Ctrl+T, sidebar and Overview creation use New Tab and focus the omnibox. Alt+Home and `browser.home` use Home in the current tab. No Home button is forced into the existing toolbar. The last-tab setting retains Startup when enabled and a blank replacement when disabled. Pending tabs count as tabs; removing one selects an existing visible tab before creating a replacement. Closing the last incognito tab returns to the normal profile and disposes private state.

`soulu://home` is a browser navigation alias for the exact packaged `file:///.../ui/home.html`, using the existing local internal-page architecture. It is not a globally registered scheme and never starts a local web server. Blank uses packaged `start.html`. HTML, CSS, JS, typography, wordmark and fallback icons are local. Weather and optional favicons never block the shell. Favicons are requested directly from a user-selected shortcut's origin, without a referrer; offline/error uses a generated local monogram. No third-party favicon service is used.

The Home bridge is distinct from the privileged shell/settings bridge. Only the exact main home document attached to its native tab can invoke `home.get`, `home.set`, `home.navigate` and `home.weather`. The native caller's tab determines profile and privacy; no caller-supplied profile ID is accepted. The response exposes only Home settings, not passwords, bookmarks or other profile data. CSP excludes external scripts, objects, connections and form targets; shortcut names and city text use textContent. HTTP(S) shortcut URLs are validated natively. Home navigation reuses the omnibox parser and the originating profile's search engine, with a web-only boundary.

Shortcuts are ordered, limited to 12, and support add, edit, delete and moving left. `homeShortcuts`, `homeWeatherCity` and individual `homeShowLogo/Search/Weather/Shortcuts/Background` switches use the existing atomic profile JSON writer. The background switch controls subtle surfaces; there is no custom image/file access. Incognito begins with a copy of the normal page settings and only mutates an in-memory private copy, cleared when the final private tab closes. The normal profile file is never written by Home's private bridge.

A graceful close writes ordered normal HTTP(S), Soulu and blank tab URLs and the last normal selected index to each profile's `soulu-session.json`. Startup `continue` restores only the launching normal profile, without an extra New Tab. Incognito and settings tabs are excluded. This is URL/order/selection restore, not navigation-history, scroll-position or crash-recovery restore. Missing or invalid snapshots fall back to Soulu. Restored URLs are validated, and snapshot size is bounded at 100 tabs.

Weather has a scoped provider boundary but no configured provider in this release. It returns `unavailable/provider-not-configured`; the compact widget expands to an honest explanation and a user-selected city. No fake conditions, automatic geolocation, API keys or secrets are used. Actual temperature/forecast integration is deferred. Recent sites, custom backgrounds, full session histories/crash recovery and Settings 2.0 are also deferred.

Validation is implemented in `scripts/test-cef-home-pages.py` and runs against the native CEF executable. The release workflow gates on these checks plus the existing storage, profiles/passwords, permissions/adblock, navigation/popups, bookmarks/Overview, Reader and layout suites. The `native_only` workflow input can build and test a reviewable runtime without producing an installer. Both keep CEF 154.0.32 / Chromium 154.0.8037.58 pinned.
